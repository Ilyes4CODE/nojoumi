{% comment %} The password-reset message. **This is not a web page and must not be written like one.** Mail clients are roughly the HTML of 1999 with different bugs in each: Outlook renders through Word, Gmail throws away everything outside , and none of them agree on flexbox, grid, or a stylesheet at all. So: tables for layout, inline CSS on every element, no class that matters, fixed 600px, and a design that survives with every image blocked. The illustrations come in as **CID attachments** rather than URLs. A remote image is blocked by default in Outlook and proxied by Gmail, so a message whose meaning depends on one arrives broken; an attached image always renders. They are **PNG** for the same reason — Outlook has no WebP, and the app's artwork is all WebP, so the email keeps its own copies. If an art file is missing, `mailer.py` leaves out both the attachment and the `cid:` reference. The message still reads correctly with nothing but type and colour, which is the state it has to be good in anyway. ## Three things that were wrong in the first version, seen in Gmail **`dir="rtl"` on does nothing.** Gmail keeps the contents of and discards the rest of the document, so the direction declared up there never reaches the text. It has to be repeated on every table and every cell that holds Arabic. The two-column row under the code was the visible casualty: the shield sat on the left of its sentence instead of the right. **`background:` is stripped where `bgcolor` is not.** Both the page tint and the lavender band behind the illustration vanished, leaving white on white. The colours are now written twice — as the attribute mail clients have honoured since 1997, and as `background-color` for the ones that prefer CSS. **The font was a name nobody has.** `Tajawal` is bundled in the APK; a mail client has no access to it, and a webfont cannot be loaded because Gmail drops and @import. It fell through to whatever the client picked for Arabic, which in Gmail is thin and hard to read at body size.
